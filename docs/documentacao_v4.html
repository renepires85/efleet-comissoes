Visão Geral

O ARGOS Comissões é o sistema da eFleet Digital para calcular, validar e registrar o pagamento das comissões dos parceiros comerciais. Substitui planilhas manuais e centraliza todo o ciclo operacional — do upload do arquivo de fechamento mensal até a confirmação do pagamento.

Propósito
Problema resolvidoSolução
Cálculo manual em planilhasUpload de arquivo → cálculo automático pela Curva C de ramp-up
Sem visibilidade para o parceiroPortal individual por parceiro com extrato, gráficos e validação
Sem controle de pagamentoFluxo gestão → parceiro → pagamento com registro de data e responsável
Sem rastreabilidadeCheckpoints por upload, histórico de validações, log de pagamentos

Views
vw_extrato_prestador

Join entre comissoes e fechamentos. Usada para exibir o extrato detalhado por parceiro. Inclui todos os status (calculada, suspensa, zerada).

vw_acumulado_prestador

Agrega o total histórico de comissões por parceiro. Usada no card "Acumulado" do extrato do parceiro. Retorna null quando o parceiro não tem comissões — sempre usar .maybeSingle(), nunca .single().

vw_dashboard_gestao

Agrega os totais por parceiro para o dashboard de gestão — FUEL, mensalidades, suspenso, total e status.

⚠️
As views precisam de GRANT explícito para service_role quando criadas com "Automatically expose new tables" desmarcado. RLS sozinho não é suficiente.
6
Funções SQL
processar_comissoes(p_upload_id uuid) → integer

Função principal de cálculo. Para cada linha de fechamento vinculada ao upload, calcula a comissão de cada produto ativo. Usa SECURITY DEFINER para contornar RLS. Retorna o número de linhas calculadas.

Lógica: Join fechamentos + prestadores pelo nome → para cada produto com ativação e receita → calcula mês da curva → aplica fator de ramp → multiplica base × taxa × fator → insere em comissoes com ON CONFLICT DO NOTHING.

-- Taxas por produto
FUEL:    receita × 0.20 × fator_ramp
PASS:    receita × 0.15 × fator_ramp
FINES:   receita × 0.15 × fator_ramp
PREMIUM: receita × 0.15 × fator_ramp
criar_validacoes_pendentes(p_upload_id uuid)

Cria um registro em validacoes_mensais para cada prestador distinto no upload. Status inicial: pendente. Chamada automaticamente após processar_comissoes no fluxo de upload.

calcular_mes_curva(data_ativacao date, periodo_fim date) → integer

Calcula o mês da Curva C. Fórmula: ((ano_fim - ano_at) × 12 + (mes_fim - mes_at)) + 1.

calcular_fator_ramp(mes_curva int) → numeric

Retorna o fator de ramp-up conforme o mês da curva. Veja tabela completa na seção Regras de Negócio.

gerar_codigo_prestador(p_nome text) → text

Gera um código único para o prestador baseado no nome. Usado no cadastro manual de novos parceiros.

🚨
Toda função que escreve em tabelas protegidas por RLS DEVE ser criada com SECURITY DEFINER. Sem isso, a função falha silenciosamente ou retorna 0 registros.

Janela de Comissão

Cada produto tem uma janela de 12 meses a partir da data de ativação. No mês 13 em diante, o fator de ramp é 0 e a comissão é zerada automaticamente. O sistema exibe um alerta ⚠ no extrato quando o cliente está no mês 11 ou 12.

13
Armadilhas Conhecidas
RLS sem GRANT → silêncio total
Funções com SECURITY DEFINER que escrevem em tabelas protegidas precisam de GRANT explícito para service_role. Sem o GRANT, a função executa, retorna sucesso, mas não insere nada. Sempre executar: GRANT ALL ON tabela TO service_role;
.single() com resultado vazio → erro 406
Quando uma query retorna zero linhas e usa .single(), o Supabase retorna erro 406 Not Acceptable. Sempre usar .maybeSingle() quando o resultado pode ser nulo — especialmente em vw_acumulado_prestador para parceiros sem comissões.
prestador_id nulo em fechamentos → sem validações
O campo prestador_id em fechamentos é preenchido no upload via match de nome (vendedor_nome = prestadores.nome, case-insensitive). Se os nomes não baterem exatamente, o prestador_id fica nulo e nenhuma validação é criada. Sempre verificar a grafia dos nomes.
Editar arquivo grande no GitHub → perda de conteúdo
O editor do GitHub em mobile pode truncar arquivos grandes. Para edições em index.html ou vendedor.js, copiar o conteúdo para TextEdit primeiro, editar, e colar o arquivo completo de uma vez.
inline onclick → event listener perdido
Nunca usar onclick inline no HTML. Todos os event listeners devem ser registrados dentro do DOMContentLoaded em app.js. Listeners inline não são reconhecidos pelo sistema de perfis e podem causar falhas silenciosas.
app.js sobrescrito com conteúdo errado
Durante a sessão de desenvolvimento, o arquivo app.js foi acidentalmente sobrescrito com o conteúdo de solicitacoes.js, causando falha total no login. Sempre verificar o conteúdo do arquivo no GitHub antes de commitar.
Ban no Auth não propaga automaticamente
Inativar um parceiro em prestadores.ativo não bloqueia o acesso automaticamente. O bloqueio exige uma chamada explícita ao smart-service com action: 'atualizar_usuario' e ativo: false. A comparação entre ativo anterior e novo deve ser feita antes de salvar.
Corte de custo em mês N → efeito em N+1
Cortes executados em um mês só geram redução de receita no mês seguinte. Projeções devem refletir isso corretamente.
